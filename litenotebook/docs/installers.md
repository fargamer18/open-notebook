# Installers

LiteNotebook has an installer for each platform. Both install the program
only. AI models, llama.cpp, speech voices and notebooks are never part of an
installer: after installation LiteNotebook's own first-run wizard detects the
hardware, recommends components and downloads them only when you approve.

```
OS installer → launch LiteNotebook → first-run wizard → hardware detection
→ recommendations → downloads you approve
```

## Windows: `LiteNotebook-Setup-<version>-x64.exe`

An Inno Setup wizard (`packaging/windows/litenotebook.iss`, Inno Setup 6.4+),
built by `tools/build.py` on Windows.

| Page | Content |
|---|---|
| Welcome | standard |
| Information | what is installed, where your data lives, licences and notices, the unsigned-installer note (`packaging/windows/before-install.txt`) |
| Install location | default `%LOCALAPPDATA%\Programs\LiteNotebook` (per user). A folder inside `%LOCALAPPDATA%\LiteNotebook` (your data) is refused |
| Components | **LiteNotebook (required)**; **[ ] Install local semantic-search runtime**: "enables local embeddings and semantic search (needed to add new PDFs). Approximately 1 GB installed." Unticked on a first install |
| Shortcuts | **[x] Create Start Menu shortcut**, **[ ] Create Desktop shortcut** (the LiteNotebook icon) |
| Ready to Install | summary of the choices |
| Progress | standard |
| Finish | **[x] Launch LiteNotebook** (a windowed program: no console window) |

- **No administrator rights** (`PrivilegesRequired=lowest`), x64 only.
- **No file associations**: LiteNotebook does not register for PDF files.
- **Nothing is downloaded** by the installer. The optional runtime is inside
  the installer and is installed only when ticked. This makes the installer
  larger (the runtime archive alone is ~330 MB compressed on Linux; the
  Windows size will be recorded by the first Windows build) but avoids a
  second download and any network access during setup. The same runtime is
  also published separately as
  `LiteNotebook-embedding-runtime-<v>-windows-x64.zip` for the portable zip
  and for installing later from Settings → Local AI.
- The runtime goes to `{app}\embedding-runtime`, where LiteNotebook finds it
  (`packaging.find_embed_worker`). PyTorch is only ever loaded by the separate
  worker process, never by `LiteNotebook.exe`.

**Upgrades.** The same `AppId` is used by every version, so running a newer
installer upgrades in place: the previous folder and component choices are
reused, the old `_internal` and `embedding-runtime` folders are removed
before the new files are copied (no mixing of library versions), and
`%LOCALAPPDATA%\LiteNotebook` is never touched. If LiteNotebook is running,
Setup asks to close it.

**Uninstall** (Settings → Apps, or Start Menu): removes the program files,
the shortcuts and the uninstall entry. It **keeps** `%LOCALAPPDATA%\LiteNotebook`:
notebooks, PDFs, notes, chats, backups, downloaded models and AI components.
A message says where that folder is. There is no option to delete data from
the uninstaller; delete the folder yourself if you want to.

**Silent install** (IT / CI):
`LiteNotebook-Setup-0.9.3-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
[/DIR="…"] [/COMPONENTS=app,runtime] [/TASKS=startmenuicon,desktopicon]`.

**Status:** the script compiles with Inno Setup 6.4.3. Its logic (install,
upgrade from an older version, component change, refusal of the data folder,
uninstall keeping data) was exercised with stand-in files under Wine on
Linux. That is a check of the installer definition, **not** Windows
verification: the real installer has not been built or run on Windows yet
([windows.md](windows.md)).

## Linux: `install-litenotebook.sh`

A per-user Bash installer generated by `tools/build.py` for one release
(`packaging/linux/install-litenotebook.sh.in`, rendered by
`tools/linux_installer.py`). It contains the version and the exact name,
size and SHA-256 of `LiteNotebook-<v>-linux-x86_64.tar.gz` and of the
optional runtime archive, and installs only those files.

```bash
# put it next to the downloaded archives, then:
bash install-litenotebook.sh                       # interactive
bash install-litenotebook.sh --yes                 # defaults, no questions
bash install-litenotebook.sh --yes --with-embedding-runtime
#   --prefix DIR   --no-desktop-entry   --desktop-shortcut   --uninstall   --help
```

| What | Where (XDG, per user) |
|---|---|
| Program | `~/.local/opt/litenotebook/` |
| Launcher, uninstaller | `~/.local/bin/litenotebook`, `~/.local/bin/litenotebook-uninstall` |
| Menu entry | `$XDG_DATA_HOME/applications/litenotebook.desktop` |
| Icon | `$XDG_DATA_HOME/icons/hicolor/256x256/apps/litenotebook.png` (+ `scalable/…svg`) |
| Desktop shortcut (optional) | the XDG desktop folder |
| Optional runtime | `~/.local/opt/litenotebook/embedding-runtime/` |
| Your data (never touched) | `$XDG_DATA_HOME/LiteNotebook`, logs in `$XDG_STATE_HOME/LiteNotebook/logs` |

Interactive mode shows the version, location and components
(`[x] LiteNotebook`, `[ ] Local semantic-search runtime (~1 GB installed)`
when its archive is next to the installer), asks about the menu entry and a
desktop shortcut, then prints each step: Verifying…, Installing LiteNotebook…,
Installing optional runtime…, Verifying files…, Installing desktop launcher…,
Installing icon….

Safety rules:

- **No root.** It refuses to run as root; it writes only under `$HOME`.
- **No network** and no "latest" files: it installs only the archives whose
  size and SHA-256 it carries; a mismatch stops before anything changes.
- **Archive checks before extracting:** one top folder, only plain files,
  folders and relative symlinks that stay inside it; no `..`, absolute paths,
  hard links or device files; file names from a safe character set. Nothing
  from the archive is run during installation.
- **Staged replacement:** the archive is extracted and checked in a temporary
  folder next to the program folder, then swapped in with renames. If anything
  fails, the existing installation is left as it was and temporary files are
  removed.
- It refuses to replace a folder that is not a LiteNotebook installation, to
  use `$HOME` or the data folder as the program folder, and to upgrade or
  uninstall while LiteNotebook is running.
- Paths with spaces and non-ASCII characters are quoted everywhere (launcher,
  `.desktop` `Exec`, uninstaller).

**Upgrades.** Running a newer `install-litenotebook.sh` replaces the program
folder and keeps your data. A runtime from an older version is not carried
over (it belongs to its version): pass `--with-embedding-runtime` again.
Reinstalling the same version keeps its runtime.

**Uninstall:** `litenotebook-uninstall` (or `install-litenotebook.sh
--uninstall`) removes the program folder, launcher, uninstaller, menu entry,
desktop shortcut and icons that the installer created, and prints the data
folder it kept. It never deletes notebooks, backups, models or AI components;
delete `~/.local/share/LiteNotebook` yourself if you want them gone.

**Alternatives:** the AppImage (one file; needs FUSE 2, or
`--appimage-extract-and-run`) and the plain tarball (`./litenotebook
--install-desktop-entry` adds a menu entry). See [linux.md](linux.md).

## Tests

- `tests/test_linux_installer.py`: install, options, upgrade, failed upgrade,
  uninstall with data kept, refusal cases, eleven hostile/tampered archives.
- `tools/installer_smoke.py linux DIST`: the real release archives, a HOME
  with a space and "José": install → launch → create data → quit → install
  again with the runtime → data still there → uninstall → data kept.
- `tools/installer_smoke.py windows DIST [--old-installer OLD.exe]`: the same
  cycle with the real wizard, run by the Windows CI job.
- `tools/verify_release.py DIST`: names, checksums, manifest and contents
  before upload.
